## 2. 产品定位

本系统面向低空城市治理场景，围绕无人机、机库、设备、巡检任务、航线、飞行轨迹、飞行日志、照片、视频、影像、线索、事件和文档等数据资源，建设统一的数据目录、资产维护、查询预览、二维空间展示、资产关联追溯及数据服务发布能力。

系统为事件处置等外围业务系统提供标准化、可检索、可预览、可关联、可调用的数据服务。

> 本系统负责“数据资产服务”，不负责“事件怎么处置”。

---

## 3. 建设目标

1. 建立低空治理数据统一目录和资产台账。
2. 统一管理低空治理相关结构化数据、空间数据、媒体数据和文件数据。
3. 建立“无人机—巡检任务—航线/轨迹—照片/视频—线索/事件”的资产关系链。
4. 支持从任一资产回溯或下钻至关联资产，实现数据关系追溯。
5. 提供二维地图上的资产点位、航线、飞行轨迹和空间查询能力。
6. 支持数据库、文件和 API 三类数据服务发布。
7. 为事件处置系统及其他政务应用提供标准数据接口。
8. 建立数据服务调用日志和操作审计机制。

## 5. 用户角色

| 角色 | 主要职责 |
|---|---|
| 政府内部工作人员 | 按授权查询、预览和使用数据资产 |
| 项目管理人员 | 维护项目、巡检任务和相关资产关联 |
| 数据审核人员 | 对数据质量、完整性和关联关系进行审核或确认 |
| 领导/监管人员 | 查看资产总览、地图分布、关联数据和服务情况 |
| 系统管理员 | 管理目录、资产类型、数据源、服务、用户、角色、权限和日志 |

### 5.1 权限模型

系统采用 RBAC（基于角色的访问控制）模型。

建议将以下权限设置为独立权限点：

- 查看
- 预览
- 下载
- 编辑
- 删除
- 恢复
- 导入
- 导出
- 关联维护
- 发布
- 停用
- 服务调用
- 日志查看

数据权限一期按角色控制；组织级、项目级和资产级数据隔离作为可扩展能力，并列入待确认项。

### 7.3 项目归属规则

1. 巡检任务必须归属项目。
2. 无人机、机库、其他设备和航线属于可复用基础资产，不强制只属于一个项目。
3. 照片、视频、飞行轨迹、飞行日志等作业成果通过巡检任务间接归属项目。
4. 线索和事件可以通过任务、照片、视频或影像建立项目关联。
5. 无法匹配项目或任务的数据进入“待匹配/待归属数据”列表。

## 8. 资产关联与关系追溯

资产关联是本系统的核心能力。系统需要支持直接关联、间接关联、自动关联、人工补充关联、批量关联和关联审计。

### 8.1 核心关系模型

```mermaid
flowchart LR
    A[无人机A] --> B[巡检任务]
    C[无人机机库] --> A
    D[其他设备] --> B
    B --> E[航线]
    B --> F[飞行轨迹]
    B --> G[飞行日志]
    B --> H[照片]
    B --> I[视频]
    B --> J[影像]
    H --> K[线索]
    I --> K
    J --> K
    H --> L[事件]
    I --> L
    J --> L
    K --> L
    B --> M[文档]
    L --> M
```

### 8.2 典型关系

| 关系 | 建议基数 | 说明 |
|---|---|---|
| 机库—无人机 | 一对多 | 一个机库可管理多架无人机 |
| 无人机—巡检任务 | 一对多 | 一架无人机可执行多个巡检任务 |
| 巡检任务—航线 | 多对多或多对一 | 记录任务使用的航线及版本 |
| 巡检任务—飞行轨迹 | 一对一或一对多 | 记录任务飞行过程 |
| 巡检任务—飞行日志 | 一对多 | 记录任务运行日志 |
| 巡检任务—照片 | 一对多 | 记录任务产生的照片 |
| 巡检任务—视频 | 一对多 | 记录任务产生的视频 |
| 巡检任务—影像 | 一对多 | 记录任务产生的影像 |
| 照片/视频/影像—线索 | 多对多 | 作为线索依据或证据 |
| 照片/视频/影像—事件 | 多对多 | 支持事件直接关联证据 |
| 线索—事件 | 一对一或一对多 | 线索可形成事件或关联事件 |
| 事件—文档 | 一对多 | 形成事件材料归档关系 |

### 8.3 关联方式

#### 自动关联

系统依据外部平台提供的信息自动建立关系，包括：

- 外部任务编号
- 外部资产编号
- 无人机序列号
- 项目编号
- 航线编号
- 媒体唯一标识
- 线索编号
- 事件编号
- 拍摄时间
- 空间位置

#### 人工补充关联

授权用户可以：

- 选择关联资产
- 批量关联照片或视频
- 补充项目归属
- 修改错误关联
- 解除关联
- 填写关联说明

#### 待匹配数据

自动关联失败的数据进入待匹配列表，记录：

- 数据名称
- 数据类型
- 外部来源
- 外部唯一标识
- 失败原因
- 推荐匹配对象
- 当前处理状态
- 处理人
- 处理时间

### 8.4 关系追溯要求

系统应支持：

- 查看直接关联资产
- 查看间接关联资产
- 按资产类型筛选关联对象
- 按时间和项目筛选关联对象
- 从无人机追溯到巡检任务、照片、视频和事件
- 从事件回溯到照片、视频、巡检任务和无人机
- 从照片或视频下钻到任务、设备和事件
- 查看关联来源和关联操作记录
- 通过关系图谱查看完整链路

## 10. 功能需求

## 10.1 数据资产总览

### 功能说明

提供低空治理数据资产的整体概览，帮助用户快速了解资产规模、数据质量和服务状态。

### 功能要求

- 展示资产总量
- 按资产类型统计数量
- 按目录统计资源数量
- 展示照片、视频和文档数量
- 展示空间数据数量
- 展示已发布服务数量
- 展示启用/停用 API 数量
- 展示最近更新资产
- 展示最近发布服务
- 展示导入失败数据
- 展示待匹配数据数量
- 展示服务调用概况

- 新增子节点

- 设置可见性
- 删除节点

- 调整节点排序

- 资源名称

- 资源编码
- 数据类型
- 数据格式分类
- 数据格式类型
- 数据格式描述
- 共享方式
- 更新周期
- 创建时间
- 信息项列表

## 11. 核心业务流程

### 11.1 外部数据同步与自动关联

```mermaid
flowchart TD
    A[外部平台产生数据] --> B[同步任务启动]
    B --> C[同步任务/照片/视频/轨迹/日志]
    C --> D[校验外部唯一标识]
    D --> E[匹配项目和巡检任务]
    E --> F{是否匹配成功}
    F -->|是| G[建立资产关联]
    F -->|否| H[进入待匹配数据]
    G --> I[进入资产查询和服务目录]
    H --> J[授权人员人工匹配]
    J --> G
```

### 11.2 Excel 导入

```mermaid
flowchart TD
    A[下载标准模板] --> B[填写资产数据]
    B --> C[上传Excel]
    C --> D[字段和数据校验]
    D --> E{校验结果}
    E -->|通过| F[正式导入]
    E -->|部分失败| G[生成失败明细]
    E -->|关联失败| H[进入待匹配列表]
    G --> I[修正后重新导入]
    H --> J[人工补充关联]
    F --> K[生成导入记录]
```

### 11.3 数据服务发布

```mermaid
flowchart LR
    A[配置数据源] --> B[获取表/文件]
    B --> C[选择资产和字段]
    C --> D[配置服务参数]
    D --> E[连通性测试]
    E --> F{测试通过}
    F -->|是| G[发布服务]
    F -->|否| H[修改配置]
    H --> E
    G --> I[生成API]
    I --> J[生成使用手册]
    J --> K[记录调用日志]
```

## 14. 权限、安全与审计

### 14.1 权限

- 采用 RBAC。
- 查看、预览、下载、编辑、删除、恢复、导入、导出、关联维护、发布、停用独立控制。
- 视频、影像、文档和原始文件下载按角色控制。
- 领导/监管人员默认以查看和预览为主。
- 系统管理员负责配置用户、角色、目录、服务和权限。

### 14.2 数据安全

- 逻辑删除优先于物理删除。
- 回收站支持恢复。
- 数据源密码、FTP 密码和接口密钥不得明文展示。
- 文件访问地址不应直接暴露敏感存储路径。
- 视频和文件下载应记录审计日志。
- API 访问应支持身份认证。
- API 可配置访问限流和配额，具体策略待确认。

### 14.3 操作审计

以下操作必须记录：

- 资产新增、编辑、删除和恢复
- 目录新增、编辑、删除和发布
- 资产关联、解除关联和批量关联
- 数据源新增、编辑、删除和测试
- 服务发布、启用、停用和删除
- API 注册、编辑、启停和删除
- 文件预览和下载
- API 调用
- 用户和权限变更

## 18. 需求结论

本系统的核心不是单纯的无人机台账，也不是事件处置系统，而是一个面向低空治理场景的专业数据资产服务平台。

其核心价值可以概括为：

> **统一目录、统一资产、统一关联、统一空间查询、统一服务发布。**

最关键的产品设计原则是：

1. 以数据目录组织资产。
2. 以巡检任务作为作业数据的核心关联枢纽。
3. 以资产关系链支撑数据追溯。
4. 以二维地图承载空间数据查询。
5. 以数据库、文件和 API 发布支撑外围系统调用。
6. 将事件处置作为外围系统，通过标准数据服务进行协同。
